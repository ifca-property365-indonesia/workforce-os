# i18n conventions (apps/web)

Languages: `id` (Bahasa Indonesia) and `en` (English). Library: `next-intl` v4 without locale routing. The locale
comes from the user's preference, then the workspace default, then the `wfos_locale` cookie or `Accept-Language`, and
finally English (`src/i18n/locale.ts`).

## Catalogs

- One JSON file per namespace: `apps/web/messages/<locale>/<namespace>.json`. Namespaces are listed in
  `src/i18n/namespaces.ts`.
- `en` and `id` must have **exactly the same keys** and the same ICU placeholders (`{name}`, `{count, plural, …}`).
- Keys are camelCase and grouped by screen section, e.g. `settings.claude.title`, `settings.claude.save`.
- Shared words live in `common` (`common.save`, `common.cancel`, …). Enum labels live in `status`
  (`status.task.RUNNING`, `status.approval.PENDING`, `status.employee.ACTIVE`, `status.autonomy.DRAFT`,
  `status.autonomyDescription.DRAFT`, `status.role.OWNER`, `status.outputLanguage.inherit`).
- Server error messages live in `errors` and are translated on the server. The client just shows
  `ApiError.message`.

## In components

```tsx
"use client";
import { useTranslations } from "next-intl";
import { useFormat } from "@/lib/use-format";

export function Example({ count, when }: { count: number; when: string }) {
  const t = useTranslations("settings");   // one translator per namespace
  const tc = useTranslations("common");
  const f = useFormat();                    // dates, numbers, money, relative time, credits
  return (
    <div>
      <h2>{t("claude.title")}</h2>
      <p>{t("claude.updated", { when: f.dateTime(when) })}</p>
      <p>{t("members.count", { count })}</p>      {/* "{count, plural, one {# member} other {# members}}" */}
      <Input placeholder={t("claude.secretPlaceholder")} />
      <Button>{tc("save")}</Button>
    </div>
  );
}
```

- Server components: `const t = await getTranslations("ns")` from `next-intl/server`.
- Always pass a **string literal namespace** to `useTranslations`/`getTranslations` and a **string literal key** to
  `t(...)` so the i18n test can check that the key exists. For enum-driven keys, use a template whose prefix is a real
  group: ``t(`task.${status}`)`` with `useTranslations("status")`.
- Rich text: `t.rich("key", { b: (c) => <b>{c}</b>, code: (c) => <code>{c}</code> })` with the message
  `"Run <code>claude setup-token</code>"`.
- Formatting: never `toLocaleString()`/`toFixed()` for display and never hand-built "5m ago". Use `useFormat()`:
  `f.dateTime`, `f.date`, `f.time`, `f.ago`, `f.number`, `f.credits`, `f.usd`, `f.money(amount, currency)` (IDR →
  `Rp 1.234.567` in `id`), `f.ms`.
- `@/lib/format` no longer exports `credits/usd/ago/dateTime/ms/STATUS_LABEL`. Use `useFormat()` and the `status`
  namespace. `STATUS_TONE` (CSS classes) is still exported.
- `toast.*(...)` and `confirm(...)` take translated strings.
- Brand and technical tokens that are identical in both languages (`Workforce OS`, `Claude`, `SMTP`, `MCP`,
  `cron`, …) may stay literal. For anything else that must stay literal (a code sample, an example email
  placeholder), put a `// i18n-ignore` comment on the line or the line above. Use this rarely.

## Indonesian style

Natural, professional Bahasa Indonesia as used in Indonesian SaaS products: "Simpan", "Batal", "Pengaturan",
"Karyawan", "Tugas", "Persetujuan", "Anggaran", "Klien", "Rutinitas", "Basis pengetahuan", "Tim", "Pemilik", "Anggota".
Keep established English product terms when Indonesian users use them that way: "workspace", "dashboard", "dry run",
"replay", "token", "prompt", "webhook", "allow-list", "kill switch". Address the user formally ("Anda").

## The check

`apps/web/test/i18n.test.ts` (run with `pnpm --filter @wfos/web test`) fails on:
hard-coded JSX text, UI attributes (`placeholder`, `title`, `aria-label`, `alt`, `label`, `description`), UI
properties in object literals (`label: "…"`), string literals in `toast`/`confirm`, unknown keys, id/en drift,
placeholder mismatches, and `HttpError` without a translated `code`.
